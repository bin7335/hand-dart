# 손짓 다트

박람회 부스에서 "어떤 체험을 할지" 골라 주는 손 인식 다트판이에요.
웹캠 앞에서 **손바닥을 보여 주고 → 주먹을 쥐어 다트를 잡고 → 손을 펴면** 다트가 날아가 꽂힌 칸의 체험이 정해져요.

## 입구에서 한 번에 체험하기 (다트 → 체험 선택 → 체험)

부스 안까지 들어올 시간이 없는 손님이 입구 화면 하나로 체험까지 해 보는 흐름이에요.

1. **다트**: 손으로 다트를 던져요. 꽂힌 칸이 "다트가 고른 체험"이에요.
2. **체험 선택**: 카드가 칸마다 한 장씩 나와요. 다트가 고른 카드에는 표시가 붙어요.
   **자동으로 넘어가지 않아요.** 손을 올려 두기만 해서도 넘어가지 않아요. 하고 싶은 카드 위에서 **주먹을 꽉 쥐어야**(약 0.6초) 선택돼요. (마우스 클릭·터치도 돼요)
   선택 화면에서는 오른쪽 칸(AI가 보는 화면 등)을 치우고 화면을 가득 써요.
   아무도 없이 20초가 지나면 다트로 돌아가요.
   카메라가 켜져 있으면 **MR 모드**로 떠요. 거울처럼 비친 카메라 영상 위에 반투명 카드가 떠 있고, 고리 모양 커서가 화면 속 내 손을 따라다녀요. 주먹을 쥐면 고리가 차오르고 다 차면 선택돼요. 카드는 손이 잘 잡히는 가운데 영역에만 놓여요. (카메라 없이 쓸 때는 종이 카드 화면으로 떠요)
3. **체험**: 고른 체험이 화면 가득 열려요. 여기서부터는 그 체험의 원래 조작(마우스·키보드·카메라)을 그대로 써요.
4. **처음으로**: 화면 위쪽의 **처음으로** 버튼(또는 `R`)을 누르면 다트로 돌아가요.

체험 주소는 설정(S)의 "다트판 칸과 체험 주소"에서 칸마다 넣어요. 주소가 비어 있는 칸은 "부스 안에서 체험해요"라고만 알려 주고 처음으로 돌아가요.
모든 칸의 주소가 비어 있거나 "체험 선택 화면"을 끄면 예전처럼 결과만 보여 주고 다음 사람으로 넘어가요.

알아 둘 점:

- 체험이 열려 있는 동안 다트는 카메라를 꺼요(체험이 웹캠을 쓸 수 있게). 돌아오면 다시 켜요.
- **다른 주소(다른 사람이 만든 체험)** 는 그 화면을 한 번 누른 뒤에는 `R`·`F1`-`F4`가 듣지 않아요. 브라우저가 막기 때문이에요. 위쪽 **처음으로** 버튼을 마우스나 터치로 눌러요.
  같은 주소에 있는 체험(예: 이 앱을 `bin7335.github.io/hand-dart/`에서 열었을 때의 `bin7335.github.io/...` 체험)은 그 안에서도 키가 들어요.
- 체험 화면은 이 앱과 별개의 페이지예요. 인터넷이 필요한지, 카메라 영상을 어떻게 다루는지는 각 체험을 따라요.

## 실행

웹에서 바로 열기: https://bin7335.github.io/hand-dart/
한 번 열어 두면 인터넷이 끊겨도 같은 기기·같은 브라우저에서 계속 동작해요.

내 컴퓨터에서 실행(인터넷이 전혀 없을 때):

1. `start.bat`을 더블클릭해요. (Node.js 필요. 직접 실행: `node serve.mjs`)
2. 브라우저에서 `http://localhost:5173/` 이 열리면 카메라를 고르고 **카메라 켜고 시작하기**를 눌러요.
3. `F`를 눌러 전체 화면으로 바꿔요.

인터넷 없이 동작해요. 손 인식 모델과 라이브러리가 `vendor/mediapipe/`에 들어 있어요.
카메라는 `localhost`(또는 https)에서만 켜지므로 `index.html`을 더블클릭해서 열면 안 돼요.

## 부스 장비

- 노트북 + 외부 대형 모니터 + USB 웹캠(모니터 위에 올리기)
- 관람객은 화면 앞 1-1.5m에 서요. 오른쪽 카메라 화면의 점선 네모 안에 손이 들어오면 돼요.
- 손 뒤가 너무 밝으면(창가, 조명 역광) 인식이 떨어져요.

## 운영 단축키

| 키 | 동작 |
|---|---|
| 스페이스바 | 지금 조준점으로 바로 던지기 (결과 화면에서는 넘기기, 체험 선택 화면에서는 다트가 고른 체험 열기) |
| 마우스 클릭 | 누른 자리로 던지기 |
| R | 처음으로(체험 선택·체험 화면을 닫고 다트로) |
| F1-F4 | 1-4번 칸의 체험을 바로 열기(다트를 건너뛰기) |
| S | 설정 |
| F | 전체 화면 |
| P | 성능 표시(화면 fps, AI 분석 횟수·시간) |

## 설정 (S)

- **다트판 칸과 체험 주소**: 2-8칸, 이름과 색, 한 줄 설명(선택 화면에서 그 카드에 손을 올리면 보여요), 그 칸에서 열 체험 주소(`https://…`). 기본은 4칸(AI 코딩 공방·집중력 레벨 테스트·거북목 자세 진단·AI가 알려주는 관상)이에요.
- **체험 선택 화면**: 다트 뒤에 카드로 고르는 화면을 쓸지 정해요.
- **판 회전 속도**: 0이면 멈춘 판(겨눈 대로), 빠를수록 운이에요.
- **운의 크기**: 다트가 조준점에서 벗어나는 정도예요. 기본은 "반쯤 운".
- **다트가 날아가는 시간**: 길수록 날아가는 동안 판이 더 돌아서 운이 커져요. 기본은 약 1.9초.
- **손동작 판정**: 주먹·손바닥을 얼마나 후하게 알아볼지 정해요. 기본은 "후하게".
- **정중앙 자유 선택**: 가운데 별에 꽂히면 원하는 체험을 고르게 해요.
- **결과 보여 주는 시간**, **효과음**, **카메라**.

설정은 이 브라우저에만 저장돼요. 빗나감은 없어요. 판 밖을 겨눠도 가장자리에 꽂혀요.

## 개인정보

카메라 영상은 이 컴퓨터의 브라우저 안에서만 분석하고, 저장하거나 어디로도 보내지 않아요. 다트와 체험 선택 화면의 외부 요청은 0건이에요(자동 테스트로 확인).

체험 선택에서 여는 체험은 별개의 페이지라서 위 약속이 그대로 적용되지 않아요. 체험마다 따로 확인해요.

MediaPipe 1.2.2는 사용 통계(영상이 아닌 성능·사용량 수치)를 구글 서버(`odml.pa.googleapis.com`)로 보내려고 해요. 끄는 옵션이 없어서 `index.html`의 CSP(`connect-src 'self'`)로 막아 두었어요. 그래서 개발자 도구 콘솔에 "Refused to connect" 오류가 한 번 찍히는데 정상이에요. CSP 줄을 지우면 통계가 전송되니 지우지 마세요. 체험 화면을 열 수 있게 `frame-src`는 https 주소와 localhost를 허락해 두었어요.

## 카메라가 안 켜질 때

- Claude 앱의 미리보기 창에서는 카메라가 막혀 있어요. 크롬이나 엣지에서 `http://localhost:5173/`을 열어요.
- 주소창 왼쪽 아이콘 → 카메라가 "허용"인지 확인해요.
- 줌·카메라 앱처럼 카메라를 쓰는 다른 프로그램을 닫아요.
- USB 웹캠을 꽂은 뒤 설정(S)의 카메라 목록에서 골라요.
- 카메라 없이 시작했다면 오른쪽 위 검은 칸의 **카메라 켜기**를 눌러요.

```text
js/settings.js    설정 저장과 설정 창
js/mascot.js      도우미 캐릭터

tests/run.mjs     자동 테스트
```

## 화면이 끊겨 보일 때

`P`를 누르면 오른쪽 아래에 수치가 나와요.

- **화면 fps**가 모니터 주사율(보통 60)에 가깝고 **가장 느린 프레임**이 20ms 안쪽이면 정상이에요.
- **AI … 별도 스레드 GPU**가 정상이에요. "화면 스레드"나 "CPU"로 나오면 브라우저의 하드웨어 가속(크롬 설정 → 시스템)이 켜져 있는지 확인해요.
- 노트북을 전원에 연결하고, 다른 탭과 프로그램을 닫아요. 절전 모드에서는 fps가 30으로 떨어질 수 있어요.

## 테스트

```bash
node tests/run.mjs
```

헤드리스 크롬으로 모델 불러오기, 게임 한 판, 판정 정확도, 대체 입력, 설정 저장, 가짜 카메라 분석, 체험 선택(손 커서·주먹·자동 입장·도우미 키·카메라 넘겨주기)을 검사해요.
`IMG_DIR`에 손 사진 폴더(woman_hands.jpg, thumbs_up.jpg, victory.jpg, pointing_up.jpg)를 주면 실제 사진으로 주먹·손바닥 판정도 검사해요.
